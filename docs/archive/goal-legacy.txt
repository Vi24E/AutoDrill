5. 確定したalpha 1.0 UI仕様
   - q1設定画面は、生のHTMLに見える簡素なフォームではなく、ゲームのロビー画面のような親しみやすい完成度を持たせる
   - q1はdiep.io風の印象を参考に、中央配置、太く明快な見出しと操作部品、グレー基調、シアン系アクセント、控えめなグリッドや幾何学形状を用いる。ただし固有ロゴ・画像・意匠は複製しない
   - q1のカリキュラム木は、親から子へ選択肢が連動する3つのプルダウンで選択する
   - q1の3つのカリキュラムプルダウンは、`学年 → 領域 → 単元`の順とする
   - alpha 1.0の選択肢は、学年`小学1年生`、領域`数と計算`、単元`1けたのたしざん(1)`を表示する
   - q1を刷新しても、q2以降の問題用紙は装飾のない完全な白紙形式を維持する
   - q2の上部リボンはviewport上端へ固定し、問題をスクロールしても常に操作できるようにする
   - q2の画面上キーボードはviewport下端へ固定し、問題用紙の末尾までスクロールしなくても常に操作できるようにする
   - 画面上キーボードの数字は通常の10キーと同じく`7 8 9`、`4 5 6`、`1 2 3`、`0`の順に配置し、確定・削除などの制御キーを隣接させる
   - q2では回答欄を選択した後、物理キーボードの数字・Enter・Backspace・Delete・左右矢印を確実に受け付ける
   - 回答文字列は回答枠内で右方向へ伸び、問題式側へめり込まないようにする
   - 回答ASTは自身の構造的な大きさを返す`size`機能を持つ
   - alpha 1.0の整数回答では、数字1文字をAST size 1として数え、回答AST sizeの上限を18とする
   - 入力によって回答AST sizeが18を超える操作は受理せず、回答状態を変更しない
   - 回答AST size上限を超えた入力時は、固定リボン付近の上側へ`式が大きすぎます！`とアプリ内通知を表示する
   - 将来の複合回答型では親ノードもsize 1として数える。例として`frac(num(12), num(42))`のsizeは、`frac` 1と数字4の合計5とする
   - ドリル生成後は、装飾のない白紙を中央で区切り、問題を2列に並べる
   - 各問題は `2 + 3 = [ ]` の形で表示し、回答欄は長方形の枠にする
   - 回答欄をクリックすると画面上の10キーと制御キーを表示する
   - 画面上の10キーに加え、物理キーボードから数字入力と確定を行えるようにする
   - Enterで現在の入力を確定し、次の問題へ移動する
   - PDFビューアーのツールバーに相当する上部領域へ、単元名、回答時間、採点ボタンを表示する
   - 採点は全問題を対象に一括実行する
   - 採点を実行した時点で回答時間を停止する
   - 採点後の誤答・未回答の回答枠は`#e01010`の太枠で表示する
   - 採点後の誤答・未回答には、回答枠の右隣へ正しい答えを`#e01010`の文字で表示する
   - 問題の通し番号は、問題式との主従を保ちながら現状より大きく表示する
   - 印刷時は操作UIを非表示にし、問題ページと解答ページを分離する
   - 印刷時の解答ページは上下逆さにし、不意に解答が目に入りにくい配置にする
   - 画面で確認した印刷レイアウトと生成されるPDFを一致させる
   - PDFの回答枠は等号の直後へ配置し、Web回答画面より不自然に右へ離さない
   - 問題生成画面には「作成」ボタンと「印刷」ボタンを置く
   - 生成後のリボンには、単元名、回答時間、採点ボタンに加えて印刷アイコンを置く
   - 生成画面の「印刷」と生成後リボンの印刷アイコンは、同じ印刷処理を呼び出す
   - 日本の典型的な縦長ドリルの2列レイアウトを踏襲する
   - ドリル本体は白黒とし、色、キャラクター、背景模様、装飾枠を使用しない
   - 印刷用レイアウトは、どの画面から印刷しても同一にする
   - q1は設定画面、q2はWeb上回答画面、q3は別タブのPDFビューアーで開く印刷画面とする
   - q1の「問題生成」ボタンで、設定した問題を生成してq2へ遷移する
   - q1の「印刷」ボタンで、設定した問題を生成してq3を別タブで開く
   - q2の印刷アイコンで、表示中の問題セットを使ってq3を別タブで開く
   - q1の「問題生成」または「印刷」を押すたびに、新しい問題セットを生成する
   - q2の印刷アイコンでは再生成せず、現在表示中の問題セットをそのまま使う
   - 設定画面には、再現可能な問題生成に用いるSeed入力欄を置く
   - Seed入力欄はq1だけに表示し、q2には表示しない
   - q1のSeedが空欄なら、ボタンを押すたびに自動Seedを生成して新しい問題セットを作る
   - q1のSeedが入力済みなら、そのSeedを使い、同じSeedから同じ問題セットを再現する
   - 自動生成・入力指定のどちらでも、実際に使用したSeedを問題セットへ保存する
   - Seedに使える文字は、`1-9`、`a-z`、`A-Z`から`I`、`l`、`O`を除いた文字集合とする
   - 手入力Seedは1〜16文字をすべて許容し、空文字列は自動Seed生成の指定として扱う
   - 自動生成Seedは、テストを簡単にするため必ず4文字とする
   - 許容外文字や17文字以上の手入力に対するUI挙動はalpha 1.0では決定せず、後続版で定める
   - 問題ページの右下へ、生成日と実際に使用したSeedを小さく目立たない形で記録する
   - 印刷PDFでは、問題ページと上下逆さの解答ページの両方の右下へ、同じ生成日とSeedを記録する
   - q2の「TOPに戻る」ボタンでq1へ戻る
   - q3は、ブラウザ内で実際のPDFデータを表示する
   - alpha 1.0の一桁足し算は、1枚を2列10行の20問に固定する
   - 20問という値はアプリ全体の定数にせず、一桁足し算分野の既定値として管理する
   - 将来は、問題数と用紙の行列構成を分野ごとに定義できるようにする
   - alpha 1.0では難易度による生成条件の変更を実装しない
   - 設定画面の分野と難易度は、将来拡張の位置を示すプルダウン型プレースホルダーだけを表示する
   - alpha 1.0の問題生成器は、画面上の分野・難易度プレースホルダーにかかわらず一桁足し算の固定設定を使用する
   - alpha 1.0の学年は「小学1年生」を表示するだけのプルダウン型プレースホルダーにする
   - 分野は将来の拡張で木構造になるため、平坦な文字列一覧として設計しない
   - alpha 1.0の選択済みカリキュラムパスは `root → 小学1年生 → 1けたのたしざん(1)` とする
   - 将来、深さが増えるカリキュラム木を選択できるUIへ交換できるデータ構造にする
   - alpha 1.0の一桁足し算では、左右の数をそれぞれ1〜9とする
   - 許容する答えの範囲は1〜18とする。左右が1以上のため、実際に生成される最小値は2になる
   - 同じ順序の式は同一セット内で重複させない
   - `2+3` と `3+2` は異なる問題として扱い、同じセット内に共存できる
   - 1〜9の順序付き組から一様に生成し、既出の式が出た場合は再生成する
   - 重複再生成が無限に継続しないよう、生成処理に明示的な打切り機構とエラーを持たせる
   - 問題生成は、将来の分野を含めて通常100ms以内に完了する前提とする
   - 生成開始から100msを超えた場合は、タイムアウトエラーを返す
   - 重複再生成などが規定の最大試行回数を超えた場合は、試行上限エラーを返す
   - タイムアウトと試行上限は、呼び出し側が区別できる別のエラー形式にする

7. 確定したq2追加仕様
   - 2列の問題番号は縦方向に進め、左列を1〜10、右列を11〜20とする
   - 画面上キーボードは回答欄をクリックしたときだけ表示し、生成直後・採点後・「問題に戻る」直後は非表示にする
   - 画面上キーボードから`Del`キーを削除する。物理キーボードのDelete入力は既存仕様どおり受け付ける
   - Enterまたは画面上の確定で次の問題へ移動したとき、次の1問が操作しやすい位置へ自動スクロールする
   - 選択中の回答欄には、`EditorState.cursor`に対応する入力カーソルを表示する
   - 回答の文字サイズは回答AST sizeに応じて縮小できるが、下限を11pxとし、回答枠も実際の文字表示に合う寸法へ調整する
   - 採点後に「問題に戻る」ボタンを表示する。既存回答を保持して回答モードへ戻り、停止していたタイマーを再開する
   - 採点後に「もう一回問題を解く」ボタンを表示する。同じ問題セットを使い、回答と採点結果を消去してタイマーを0から開始する
   - 採点後に「別の問題を解く」ボタンを表示する。同じ分野で新しいランダムSeedの問題セットを生成し、回答と採点結果を消去してタイマーを0から開始する
   - Web UIでユーザーへ表示する漢字には、ふりがな表示がONのときすべてルビを振る
   - q1の「今日のステージを選んで、20問のドリルを始めよう。」というサブタイトルは表示しない
   - q1の右上へ、ふりがな表示をON/OFFするチェックボックスを置く
   - ふりがな表示は初回の既定値をONとする
   - q1で変更したふりがな表示設定はq2とTOPへ戻った後にも引き継ぎ、ブラウザを再読み込みしても端末内に保持する
   - ふりがな表示設定の永続化には、サーバー送信を必要としない`localStorage`を使用してよい

8. 確定したalpha 1.1仕様
   - 小学1年生から中学3年生までの学年を選択肢として用意する
   - 学年配下の未実装内容は、実在する単元プレースホルダーを作らず`Dummy1`等のDummy名で表す
   - 分野選択の上部に「おすすめ」と「学年から選ぶ」の横長な切替ボタンを置き、既定を「おすすめ」とする
   - 「おすすめ」は`ジャンル → テーマ`の2段階選択とし、alpha 1.1ではジャンル「足し算と引き算」にテーマ「一桁の足し算」を置く
   - 「学年から選ぶ」は`学年 → ジャンル → テーマ`の3段階選択とし、旧名称の「領域」を「ジャンル」、「単元」を「テーマ」と言い換える
   - 「おすすめ」は「学年から選ぶ」に登録されたテーマの部分集合であり、別のテーマ・生成器を複製して持たない
   - 小学1年生の「一桁の足し算」は「学年から選ぶ」にも登録し、「おすすめ」と同一のテーマID・生成器を参照する
   - 小学1年生から中学3年生の各学年には、未実装階層を示すジャンル`Dummy1`・テーマ`Dummy1`を置けるが、実装済みテーマは実名で併存させる
   - Dummyテーマはtree構造確認用として選択できるが、選択中は「問題生成」と「印刷」を無効化し、「このテーマはまだ利用できません」と表示する
   - 難易度は1（最も易しい）から5（最も難しい）までの5段階から選択できるようにする
   - 難易度表示は`1: とてもやさしい`、`2: やさしい`、`3: ふつう`、`4: むずかしい`、`5: とてもむずかしい`とし、既定値を3とする
   - UI、生成request、問題セットIDで同じ1〜5の難易度番号を使用する
   - n問の生成では、同一問題の重複を許して候補を8n問生成し、effort昇順に並べる
   - 候補8n問に含まれる異なる問題が2n種類未満なら、候補8n問全体を再生成する
   - bootstrap選択では、現在の候補プールから5個の独立な一様indexを得る
   - 難易度iでは、その5個のindexのi番目に小さい値が指す候補を採用する
   - 既にbootstrapへ採用済みの同一式が選ばれた場合は再抽選し、採用候補は候補プールから除く
   - この選択を`n+4`問まで行い、選ばれた問題をeffort順に並べて最小2問と最大2問を外れ値として捨てる
   - 残ったn問を同じSeed由来の乱数でrandomizeし、最終問題セット内では同一式の重複を許さない
   - 共通問題データ形式、共通解答構文木、共通問題生成interface、Seedと問題セットIDをversionedな仕様として定める
   - 問題セットIDは不可逆hashやbit-packを使わず、`{schema_version}-{numeric_theme_id}-{generator_revision}-{seed}-{difficulty}`の人間が読める可逆形式とする
   - 例としてschema version 3、theme ID 1、generator revision 3、Seed `Ab3Z`、難易度3は`3-1-3-Ab3Z-3`とする
   - `Problem.input_interface`は`answer_schema`と直交するtyped capability projectionとし、simple numericとstructured mathの入力許可を個別に返す
   - `nan_error`はboundedな解析不能raw textを保持する表示・編集用variantであり、数値や正解として暗黙に扱わず、常に不正解とする
   - Seed文字集合に`-`を含めない既存制約を利用し、区切りを曖昧にせず各生成条件を復元できるようにする
   - 問題数、テーマ名、レイアウト、generator ID等、numeric theme IDとgenerator revisionのregistry定義から一意に得られる値は問題セットIDへ重複格納しない
   - 問題セットIDから復元したgenerator revision、難易度、Seedと保存された旧generator実装により、過去の問題セットを再生成できるようにする
   - curriculum.mdのeffort基本操作を再利用可能な計算モデルとして実装し、標準解法の計算graph、操作回数vector、学年・単元・習熟度の重みを分離して扱う
   - effortは計算の手数・面倒さだけでなく、間違いやすさも評価する。`Overhead*`操作は主に間違いやすさに由来する追加コストとして扱う
   - `Transposition`（移項）の基本重みは2とする
   - 標準解法graphは複合計算を粗い一操作へ畳まず、細かな基本操作を漏れなく保持する。例えば2桁の足し算で繰り上がりが起きる場合は`Increment`のコストを加える
   - 基本操作へ`BigNum(n)`を追加し、数値の大きさに対して`log_10(n)`のコストを加える
   - `BigNum`は問題の被演算子ではなく正解ASTの大きさへ適用する。一桁の足し算では左右の数ではなく和に対する`BigNum(left + right)`を数える
   - 分数`41/57`のBigNumコストは`BigNum(41) + BigNum(57)`、小数`0.57`は`BigNum(57)`として、数式を表示・保持する文字列長に近いコストを表す
   - 操作回数ベクトルは全基本操作に対応する10次元強の固定成分を持ち、未使用操作も0として表現する
   - 操作回数ベクトルと重みベクトルを分離し、重みだけを変更して同じ標準解法graphのeffortを再計算できるようにする
   - 各テーマは基本操作の重みだけを個別に上書きでき、標準解法graphや操作回数vectorを複製しない
   - alpha 1.1の全テーマ重み倍率は一旦すべて既定値1.0とする。「一桁の足し算」の繰り上がりを強く評価する調整は後続で行う
   - `OverheadCarryPlus`、`OverheadCarryMinus`、`OverheadCarryMult`を操作成分へ追加し、基本重みをそれぞれ0.5とする
   - 繰り上がり・繰り下がりでは、桁操作としての`Increment`等と対応する`OverheadCarry*`を別々に数える
   - `OverheadNegative`は負数の表示ではなく、負数operandを含む演算ごとに1回発生する。単独の`-0.57`は演算ではないため0回とし、大きさのコストは`BigNum(57)`だけとする
   - 負数の標準解法では、a、bが正数のとき`a + (-b)`を、`a > b`なら`a - b`、`a = b`なら`0`、`a < b`なら`-(b - a)`へ変換し、`a - (-b)`を`a + b`へ変換する
   - 一般形`a + (-b)`だけは、多くの人が誤りなく`a - b`へ読み替えられる例外として、`a > b`、`a = b`、`a < b`のいずれでも`OverheadNegative`を加えない
   - operand順序を区別し、`(-b) + a`には`OverheadNegative`を加える
   - `a - (-b)`は`a + b`へ変換して計算するが例外ではないため`OverheadNegative`を加え、その他の負数operandを含む演算にも原則として加える
   - 問題データと解答ASTの数学値はbinary floating-pointへ変換せず、小数を十進係数とscaleで持つ等、桁と構造を誤差なく保持できる型を使う
   - effortの最終スカラーと`log_10`評価にはFloatを使用してよいが、Floatの表示値から元の数学値・桁列・BigNum引数を復元しない
   - 例えば`0.3`は正確な十進係数`3`とscale`1`を保持して`BigNum(3)`とし、浮動小数誤差によって`BigNum(3000000000004)`等へ変化させない
   - 共通解答ASTには、少なくとも整数、小数、分数、帯分数、ルート、負数、plus-minus、tuple、変数（x、y等）を型付きnodeとして定義する
   - 入力途中の表示表現と、採点・計算に使う正規化済みの正確な数学値を区別できる構造にする
   - 問題生成へproperty-based testingを追加する
   - 単元別URLを定め、未実装単元を検索対象へ含めない
   - 単元別URLは`/drills/{grade-slug}/{theme-slug}`とし、TOPは`/`のまま維持する
   - 学年slugは義務教育の通算学年を用い、小1〜小6を`grade-1`〜`grade-6`、中1〜中3を`grade-7`〜`grade-9`とする
   - 一桁の足し算のURLは`/drills/grade-1/one-digit-addition`とし、同テーマを選択済みの設定画面を表示する
   - おすすめと学年から選ぶは、同一テーマについて同じURLとテーマIDを共有する
   - Dummyおよび未実装テーマにはrouteを作らず、サイトマップと検索用metadataの対象にも含めない
   - 採点では数学的に正解でも期待表現と異なり、実際の回答表現に簡約可能な冗長性がある場合、正解扱いのまま問題ごとのwarningを表示する
   - alpha 1.1のwarning分類は`約分`、`冗長なマイナス`（マイナスが2回ある）、`余計な小数点`とし、複数該当時に併記できるversioned識別子としてRust/WASM境界へ含める
   - warning文言は後続で変更できるよう、判定用識別子と日本語表示文言を分離する
   - 解答入力は整数に加え、分数、帯分数、小数、ルート、マイナス、plusminus、コンマによる複数解を構造化ASTとして編集できるようにする
   - コンマによる複数解はtop-level `tuple`として保持し、整数・有限小数・分数・tupleの各要素はbinary floating-pointを介さず厳密に保持・正規化する
   - root、negative、plusminusは今回から構文nodeとして入力・表示できるようにする。rootおよびplusminusの数値評価は後続単元で定義する
   - 構造化editorは選択中の入力slotをAST path、slot内の位置をcursorとして保持し、template挿入後も各分子・分母等をクリックして編集できるようにする
   - 数式入力templateは分数、帯分数、平方根、マイナス、plusminus、コンマの形を入力前に理解できる視覚表現とし、画面下部のテンキー左側へ配置する。小数点はtemplateではなく数字キー領域の独立した`.`キーとする
   - 物理キーボードでも数字、`.`、`/`、`-`、`+`、`,`、Backspace、左右矢印、Enterを受け付ける
   - 構造化入力でもAnswerNodeのsize上限18を状態変更前に検証し、超過操作は既存の「式が大きすぎます！」通知で拒否する
   - 小数点は小数templateとして`0.□`等を表示せず、通常の10キーと同じく独立した`.`キーとして数字キー領域に配置する
   - 回答枠は一行の固定高にせず、分数・帯分数・root等のAST描画が必要とする高さへ伸び、問題式の横で上下中央に配置する
   - 構造化された数式と入力slotは回答枠および問題行で上下に切り取らない
