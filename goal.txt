5. 確定したalpha 1.0 UI仕様
   - q1設定画面は、生のHTMLに見える簡素なフォームではなく、ゲームのロビー画面のような親しみやすい完成度を持たせる
   - q1はdiep.io風の印象を参考に、中央配置、太く明快な見出しと操作部品、グレー基調、シアン系アクセント、控えめなグリッドや幾何学形状を用いる。ただし固有ロゴ・画像・意匠は複製しない
   - q1のカリキュラム木は、親から子へ選択肢が連動する3つのプルダウンで選択する
   - q1の3つのカリキュラムプルダウンは、`学年 → 領域 → 単元`の順とする
   - alpha 1.0の選択肢は、学年`小学1年生`、領域`数と計算`、単元`1けたのたしざん(1)`を表示する
   - q1を刷新しても、q2以降の問題用紙は装飾のない完全な白紙形式を維持する
   - q2の上部リボンはviewport上端へ固定し、問題をスクロールしても常に操作できるようにする
   - q2の画面上キーボードはviewport下端へ固定し、問題用紙の末尾までスクロールしなくても常に操作できるようにする
   - 画面上キーボードの数字は通常の10キーと同じく`7 8 9`、`4 5 6`、`1 2 3`、`0`の順に配置し、確定・削除などの制御キーを隣接させる
   - q2では回答欄を選択した後、物理キーボードの数字・Enter・Backspace・Delete・左右矢印を確実に受け付ける
   - 回答文字列は回答枠内で右方向へ伸び、問題式側へめり込まないようにする
   - 回答ASTは自身の構造的な大きさを返す`size`機能を持つ
   - alpha 1.0の整数回答では、数字1文字をAST size 1として数え、回答AST sizeの上限を18とする
   - 入力によって回答AST sizeが18を超える操作は受理せず、回答状態を変更しない
   - 回答AST size上限を超えた入力時は、固定リボン付近の上側へ`式が大きすぎます！`とアプリ内通知を表示する
   - 将来の複合回答型では親ノードもsize 1として数える。例として`frac(num(12), num(42))`のsizeは、`frac` 1と数字4の合計5とする
   - ドリル生成後は、装飾のない白紙を中央で区切り、問題を2列に並べる
   - 各問題は `2 + 3 = [ ]` の形で表示し、回答欄は長方形の枠にする
   - 回答欄をクリックすると画面上の10キーと制御キーを表示する
   - 画面上の10キーに加え、物理キーボードから数字入力と確定を行えるようにする
   - Enterで現在の入力を確定し、次の問題へ移動する
   - PDFビューアーのツールバーに相当する上部領域へ、単元名、回答時間、採点ボタンを表示する
   - 採点は全問題を対象に一括実行する
   - 採点を実行した時点で回答時間を停止する
   - 採点後の誤答・未回答の回答枠は`#e01010`の太枠で表示する
   - 採点後の誤答・未回答には、回答枠の右隣へ正しい答えを`#e01010`の文字で表示する
   - 問題の通し番号は、問題式との主従を保ちながら現状より大きく表示する
   - 印刷時は操作UIを非表示にし、問題ページと解答ページを分離する
   - 印刷時の解答ページは上下逆さにし、不意に解答が目に入りにくい配置にする
   - 画面で確認した印刷レイアウトと生成されるPDFを一致させる
   - PDFの回答枠は等号の直後へ配置し、Web回答画面より不自然に右へ離さない
   - 問題生成画面には「作成」ボタンと「印刷」ボタンを置く
   - 生成後のリボンには、単元名、回答時間、採点ボタンに加えて印刷アイコンを置く
   - 生成画面の「印刷」と生成後リボンの印刷アイコンは、同じ印刷処理を呼び出す
   - 日本の典型的な縦長ドリルの2列レイアウトを踏襲する
   - ドリル本体は白黒とし、色、キャラクター、背景模様、装飾枠を使用しない
   - 印刷用レイアウトは、どの画面から印刷しても同一にする
   - q1は設定画面、q2はWeb上回答画面、q3は別タブのPDFビューアーで開く印刷画面とする
   - q1の「問題生成」ボタンで、設定した問題を生成してq2へ遷移する
   - q1の「印刷」ボタンで、設定した問題を生成してq3を別タブで開く
   - q2の印刷アイコンで、表示中の問題セットを使ってq3を別タブで開く
   - q1の「問題生成」または「印刷」を押すたびに、新しい問題セットを生成する
   - q2の印刷アイコンでは再生成せず、現在表示中の問題セットをそのまま使う
   - 設定画面には、再現可能な問題生成に用いるSeed入力欄を置く
   - Seed入力欄はq1だけに表示し、q2には表示しない
   - q1のSeedが空欄なら、ボタンを押すたびに自動Seedを生成して新しい問題セットを作る
   - q1のSeedが入力済みなら、そのSeedを使い、同じSeedから同じ問題セットを再現する
   - 自動生成・入力指定のどちらでも、実際に使用したSeedを問題セットへ保存する
   - Seedに使える文字は、`1-9`、`a-z`、`A-Z`から`I`、`l`、`O`を除いた文字集合とする
   - 手入力Seedは1〜16文字をすべて許容し、空文字列は自動Seed生成の指定として扱う
   - 自動生成Seedは、テストを簡単にするため必ず4文字とする
   - 許容外文字や17文字以上の手入力に対するUI挙動はalpha 1.0では決定せず、後続版で定める
   - 問題ページの右下へ、生成日と実際に使用したSeedを小さく目立たない形で記録する
   - 印刷PDFでは、問題ページと上下逆さの解答ページの両方の右下へ、同じ生成日とSeedを記録する
   - q2の「TOPに戻る」ボタンでq1へ戻る
   - q3は、ブラウザ内で実際のPDFデータを表示する
   - alpha 1.0の一桁足し算は、1枚を2列10行の20問に固定する
   - 20問という値はアプリ全体の定数にせず、一桁足し算分野の既定値として管理する
   - 将来は、問題数と用紙の行列構成を分野ごとに定義できるようにする
   - alpha 1.0では難易度による生成条件の変更を実装しない
   - 設定画面の分野と難易度は、将来拡張の位置を示すプルダウン型プレースホルダーだけを表示する
   - alpha 1.0の問題生成器は、画面上の分野・難易度プレースホルダーにかかわらず一桁足し算の固定設定を使用する
   - alpha 1.0の学年は「小学1年生」を表示するだけのプルダウン型プレースホルダーにする
   - 分野は将来の拡張で木構造になるため、平坦な文字列一覧として設計しない
   - alpha 1.0の選択済みカリキュラムパスは `root → 小学1年生 → 1けたのたしざん(1)` とする
   - 将来、深さが増えるカリキュラム木を選択できるUIへ交換できるデータ構造にする
   - alpha 1.0の一桁足し算では、左右の数をそれぞれ1〜9とする
   - 許容する答えの範囲は1〜18とする。左右が1以上のため、実際に生成される最小値は2になる
   - 同じ順序の式は同一セット内で重複させない
   - `2+3` と `3+2` は異なる問題として扱い、同じセット内に共存できる
   - 1〜9の順序付き組から一様に生成し、既出の式が出た場合は再生成する
   - 重複再生成が無限に継続しないよう、生成処理に明示的な打切り機構とエラーを持たせる
   - 問題生成は、将来の分野を含めて通常100ms以内に完了する前提とする
   - 生成開始から100msを超えた場合は、タイムアウトエラーを返す
   - 重複再生成などが規定の最大試行回数を超えた場合は、試行上限エラーを返す
   - タイムアウトと試行上限は、呼び出し側が区別できる別のエラー形式にする
